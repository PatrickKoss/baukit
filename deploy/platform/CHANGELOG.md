# Changelog

## [Unreleased]

## [0.26.0] - 2026-11-16

- Breaking: local and e2e k3s clusters run hardened (S5). Local `platform-up.sh` and `platform-lifecycle.sh` clusters also run embedded etcd (`--cluster-init`) with leader election off for the controller manager, cloud controller manager and scheduler, and k3s's wrangler leases widened to 180s/150s/10s through `CATTLE_ELECTION_*`, because a lease lost under host starvation exits the server. `platform_local_etcd_args` prints these args for local and e2e clusters, outside `platform_k3s_server_args` so the production datastore stays undecided. `platform_k3s_server_args` in `local-git-http.sh` adds `--secrets-encryption`, an API server audit policy (`k3s/audit-policy.yaml`, log shipped by Alloy to Loki as `{service="kube-audit"}`), a Pod Security admission config that makes unlabeled namespaces enforce `baseline` and warn and audit `restricted` with only `kube-system` exempt, and `--protect-kernel-defaults`. `k3d_create_local_cluster` stops before k3d unless the host sets `vm.overcommit_memory=1`, `vm.panic_on_oom=0`, `kernel.panic=10` and `kernel.panic_on_oops=1`, and at least `fs.inotify.max_user_instances=512` and `fs.inotify.max_user_watches=524288`, which parallel clusters exhaust. Existing local clusters keep their old arguments until recreated. The e2e runner checks the Pod Security default before Kyverno, adds the `k3s-hardening` suite (encryption at rest, audit event in Loki), runs kube-bench `k3s-cis-1.9` report-only, and retries on a Docker `Pool overlaps` error with the next free `/24`, treating any overlapping IPv4 pool as taken.
- Breaking: `platform-up.sh` drops `BAUKIT_PLATFORM_GIT_PORT`. The local overlay's GitRepository names port 9418, so any other port left Flux unable to clone.
- Breaking: Flux 2.10.0 (source-controller and kustomize-controller v1.10.1, helm-controller v1.7.1, notification-controller v1.10.0). The notification `Provider` and `Alert` objects move to `notification.toolkit.fluxcd.io/v1`; v1 drops `Alert.spec.summary`, `Provider.spec.interval` and TLS or proxy settings in `Provider.spec.secretRef`, none of which the platform used. The `flux-tenant-alert-sources` policy matches `v1` and `v1beta3`. Flux 2.10 lists Kubernetes 1.35.2 as its minimum; its `>=1.35.0-0` precheck passes on the local k3s v1.37.2. `platform-up.sh` now installs the Flux version from `deploy/tools.toml` with the pinned CLI in `.tools/bin`.
- Breaking: kube-prometheus-stack 93.3.0 (from 88.6.5) with Prometheus Operator and config-reloader v0.95.2 and Thanos v0.42.5. The chart majors in between change no value the base sets: 89 moves Grafana to chart 13 (distroless image, read-only root filesystem, so the base pins `13.3.1-distroless`), 90 replaces `bearerTokenFile` on the control-plane ServiceMonitors with an `authorization` Secret (`prometheus.serviceAccount.createTokenSecret`), 91 and 93 tighten the operator ClusterRole and ship new CRDs (Flux applies them with `crds: CreateReplace`), 92 adds `nodeSelector: kubernetes.io/os: linux`. Grafana chart 14 renders a helm test pod; the base pins its bats image by digest and the HelmRelease sets `test.enable: true`, so Flux runs it after each install and upgrade.
- Breaking: Loki chart 21.2.3 (from 18.13.7). 19 stops copying service labels and annotations to headless Services, 20 removes the MinIO subchart and rejects unknown top-level values keys, 21 changes the rollout-operator webhook default; none of these touch the monolithic filesystem setup. The gateway runs nginx-unprivileged 1.31.8-alpine and the access-log-exporter 1.0.2.
- Breaking: Tempo chart 3.2.1 with Tempo 3.1.1 (from chart 2.4.0, Tempo 2.10.10). Tempo 3 removes the ingester, the compactor and the memory ballast. `tempo.ingester.max_block_bytes` becomes `tempo.liveStore.max_block_bytes`, the `compactor.compaction.compaction.max-block-bytes` flag becomes `tempo.backendWorker.compaction.max_block_bytes`, and `memBallastSizeMbs` is gone, in the base and the local overlay. Retention stays `tempo.retention`, which chart 3.2 renders into `backend_worker.compaction.block_retention`.
- Alloy chart 1.16.0 comes from `oci://ghcr.io/grafana/helm-charts/alloy` through an `OCIRepository`; the `grafana` HelmRepository in `observability-agents` is gone.
- The local alert sink runs on `python:3.15.2-alpine3.24`.
- `platform_label_system_namespaces` in `local-git-http.sh` labels the namespaces k3s creates for Pod Security: kube-system `privileged` (it is exempt in the admission config), default, kube-public and kube-node-lease `restricted` with `enforce-version` v1.37. The e2e run, `platform-up.sh up` and the lifecycle's `ensure_cluster` call it once the cluster is reachable, so `require-psa-labels` reports no failures.
- The k3d smoke, `platform-up.sh` and the lifecycle's cluster creation use the registry pull-through mirrors when all of them run, and detach them before deleting the cluster. Without running mirrors they create the cluster as before.
- Breaking: newest stable pins outside the observability stack and Flux (SC5b). Traefik chart 41.6.1 to 42.4.0 (major). Its notes need Kubernetes 1.30 or later, scope the Traefik Hub Secret write verbs to the release namespace, change the Hub transparency-log witness defaults, and add a 5s `requestAcceptGraceTimeout` on `web` and `websecure`; the base uses no Hub values, so no value moves. Redpanda v25.3.18 to v26.2.7 (major): a running PostHog Redpanda with a 25.3 volume must start once on v26.1.17 first, because Redpanda upgrades one feature release at a time. PostHog image release-1.43.0 to release-1.43.1. Local k3s v1.34.13 to v1.37.2: `k3d_create_local_cluster` and the k3d smoke now fail fast unless Docker reports cgroup v2 (on WSL2 set `kernelCommandLine = cgroup_no_v1=all` in `.wslconfig`), and every Namespace, the tenant component, the lifecycle scripts and `kyverno-policies` move their Pod Security version to `v1.37`. Tools: helm 4.3.2, kubectl 1.37.2, promtool 3.16.0, pint 0.90.0, trivy 0.76.2, and the validator image prom/prometheus v3.16.0. Everything else in this half was already on its newest stable release; the README of each base and the SC5b report give the checked reason where a newer line exists but cannot be used (PostHog's Redis, ClickHouse and PostgreSQL ranges, PostgreSQL 19 still at rc2).
- Breaking: charts that upstream publishes as OCI artifacts come from an `OCIRepository` pinned by tag and digest, and their HelmRelease uses `spec.chartRef`: cert-manager, cloudnative-pg, falco, flagger, kured, kyverno, kyverno-policies, policy-reporter, kube-prometheus-stack, loki, tempo and traefik. The `HelmRepository` objects `jetstack`, `cloudnative-pg`, `falcosecurity`, `flagger`, `kured`, `kyverno`, `kyverno-policies`, `policy-reporter`, `traefik`, `prometheus-community` and `grafana-community` are gone. cloudnative-pg, falco, flagger and policy-reporter are cosign keyless signed, and source-controller now verifies them against the release workflow identity. hcloud, alloy and posthog stay on HTTPS indexes; the chart sources table in the README gives the reason per chart, and `lint/check_chart_sources.py` fails validation when a HelmRelease disagrees with it. The `helmrepository-interval` policy is now `chart-source-interval` and covers OCIRepository too.
- Every pod a base renders sets a priority class: `platform-critical` for Traefik, cert-manager, the CNPG operator, the PostgreSQL instance, Kyverno admission and the hcloud CSI driver, `platform-standard` for everything else, including raw manifests, Helm hooks and tests. Charts without a values key get it from `postRenderers`, and `validate.sh` now applies a HelmRelease's kustomize post-renderers to its chart render. redis-ha gets a PodDisruptionBudget (`maxUnavailable: 1`). kured asks Prometheus for firing alerts before a reboot (info and `none` alerts filtered by name), and the local overlay installs kured with notifications to the alert sink. New convention rules: `priority-class`, `pdb-multi-replica` and `kured-alert-filter`.
- Pin every rendered container image by its multi-arch index digest, except the falcosidekick helm-test `curlimages/curl` listed in `lint/image-digest-exempt.toml`. PostgreSQL clusters take their image from the new `postgresql` ImageCatalog (18.7). Bumps: cert-manager chart v1.21.3, hcloud-csi chart 2.24.2, hcloud-ccm chart 1.39.3, Barman Cloud v0.16.0, Traefik v3.7.19, Alloy v1.22.0, Loki 3.7.10, Tempo 2.10.10, Grafana 13.3.1, Prometheus v3.16.0, Alertmanager v0.35.0, Redis 8.10.3, RustFS 1.0.5, aws-cli 2.40.3, Pushgateway v1.11.5, local k3s v1.34.13 and the restore-test k3s v1.37.2.
- The `image-digest` convention rule fails any rendered container, init container, helm test hook or Secret-injected image without an `@sha256` digest, and any exemption in `lint/image-digest-exempt.toml` that no longer matches. It also checks the Flux lockdown install, whose four controllers `components/flux-lockdown` now pins by digest; `flux_lockdown_verify` fails `up` and bootstrap when a live controller runs another image. `platform_images.py` scans the Barman sidecar image from the plugin Secret.
- Every HelmRelease sets a measured `timeout`, `upgrade.cleanupOnFail: true` and `driftDetection.mode: enabled`. Charts with a Helm `crds/` directory (alloy, flagger, kube-prometheus-stack, loki, posthog, traefik) install and upgrade CRDs with `CreateReplace`. Falco and Kyverno run their Helm tests (`test.enable: true`). `validate.sh` enforces these rules, exact chart versions, HelmRepository intervals of 1h or more, and `prune`/`wait` on Flux Kustomizations with offline Kyverno policies in `lint/ci-policies/`.

- Breaking: run Traefik as a Deployment behind k3s ServiceLB (`type: LoadBalancer`) instead of a hostPort DaemonSet, so rollouts no longer hang. One replica in the base, `maxUnavailable: 0, maxSurge: 1`, a PodDisruptionBudget with `maxUnavailable: 1`, `platform-critical` priority and `CreateReplace` CRD handling. The hcloud CCM Load Balancer controller is off so ServiceLB stays the only answer.

- Fix node drains on a single-instance CNPG cluster (`enablePDB: false`). The restore-test Role can patch and delete only `postgres-cluster-restore-test`, and the restore cluster takes its StorageClass from `RESTORE_STORAGE_CLASS`. The hcloud base adds the `hcloud-volumes-delete` StorageClass for it.

- Breaking: Prometheus reads rules, ServiceMonitors and PodMonitors only from namespaces labelled `app.kubernetes.io/part-of: baukit-platform`, which loads the restore-test alert in `postgres`. Application namespaces need the label to be scraped. Grafana loads dashboards from every namespace into folders named by the `grafana_folder` annotation.

- Breaking: the hcloud base no longer manages the `kube-system` Namespace. Stateful Namespaces, the CNPG Cluster and the local RustFS PVC carry `kustomize.toolkit.fluxcd.io/prune: disabled`.

- Harden the local lifecycle: the snapshot holds only files Git would commit, the snapshot server listens on the k3d network gateway, runs as non-root and validates `Content-Length`, the k3d API and ports 80/443 bind `127.0.0.1`, and `status` prints where secrets live instead of their values.
