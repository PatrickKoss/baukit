## [0.28.3] - 2026-11-19

- `platform-images` downloads trivy's vulnerability and Java databases and the checks bundle into each run's work directory, as a fresh CI runner does, and shares only the layer cache in `~/.cache/baukit/trivy/fanal`. trivy skips a download until the cached database's NextUpdate, a day for the vulnerability DB and three for the Java DB, so the local step passed on a DB from 2026-11-17 19:04 while CI's DB from 2026-11-18 13:03 reported CVE-2026-64544 and CVE-2026-64549 in the PostHog image. A local run now downloads about 1.6 GB more, roughly two minutes. The old `db` and `java-db` directories in the shared cache are no longer read and can be deleted.
- `posthog/posthog:release-1.43.1` allows CVE-2026-64544 and CVE-2026-64549 in `linux-libc-dev`. release-1.43.1 is still the newest PostHog release, so there is no fixed image.
- `image-findings.toml` allows CVE-2026-97054 in 48 images. It is a Go standard library `net/http` race (an HTTP/1 handler that reads the body behind `MaxBytesReader` while it writes the response can panic) fixed in Go 1.26.11 and 1.27.4 on 2026-11-10. Every affected image is on its newest upstream release, and none of them is built with a fixed Go yet. node-exporter v1.13.0 is tagged on GitHub but has no image. Six images get their first entry: Alloy v1.22.0, Loki 3.7.10, the Loki access-log-exporter 1.0.2, redis_exporter v1.97.0, prometheus-operator and prometheus-config-reloader v0.95.2. PostHog release-1.43.1 also allows CVE-2026-64495 (`linux-libc-dev`) and CVE-2026-73864 (`install-artifact-from-github` 1.3.1 in the plugin server's `node_modules`). Rescanned against the Trivy DB of 2026-11-19.
- redis-ha keeps the Sentinel config on a memory-backed `emptyDir` (1 Mi). Sentinel fsyncs `sentinel.conf` when it votes for itself and sends the vote request to the other Sentinel only after that write returns. Killing the master also kills its Sentinel, so the two left must both vote for the same leader. In hosted run 44098804721 the self-vote write took 67 to 485 ms, the second Sentinel started its own election before the request arrived, and both elections at 14:13:52 and 14:14:53 ended in `-failover-abort-not-elected`. No replica was promoted within the suite's 120 s. The config is rewritten at every container start, so it needs no disk.
- The platform-e2e `smoke` suite skips `chainsaw-*` namespaces when it checks Flux objects and pod restarts. Suites run in parallel, and `flux-tenancy` creates Kustomizations in its test namespace that fail on purpose, so smoke failed in runs 43920161681 and 44291934770 (after 5 s in the second).

## [0.28.0] - 2026-11-17

- BREAKING: `verify-baukit-images` and `require-image-digest` deny instead of audit. Tenant Pods with `ghcr.io/patrickkoss/*` images need a digest pin and a cosign signature from the product key (plan D6). The key comes from the overlay-owned ConfigMap `kyverno/baukit-image-signing-key` (`cosign.pub`), and Kyverno reads GHCR with the dockerconfigjson Secret `kyverno/baukit-image-verify-registry`. Before pinning this release: sign and digest-pin every deployed product image, add both objects to the cluster overlay, and label production tenant namespaces `baukit.dev/environment: production`. `require-image-digest` still covers only those namespaces.
- Falco stops dropping kernel events during heavy local gates. It sets `base_syscalls.repair: true`, so the driver captures only the syscalls the loaded rules need plus the process and fd state they depend on, and raises the modern_ebpf ring buffers from 8 MiB (`bufSizePreset: 4`) to 16 MiB (`5`). With 2 CPUs per buffer a 24-CPU host gets 12 buffers, 192 MiB instead of 96 MiB. On platform-local the old config dropped 95.9 M of 2.88 G events in 10 h (3.3 %), at up to 18 k drops/s during gates, which kept `BaukitFalcoEventsDropped` firing. Most drops were `close` (14.9 M) and `connect` (2.9 M) exit events from host-wide builds, which share the k3d node's kernel. The container was CPU-throttled in 0.4 % of periods, so the limit was not the cause.
- platform-e2e fails on any kube-bench `k3s-cis-1.9` FAIL; WARN (manual checks) stays report only. 21 of the 26 FAILs were audits that read k3s's component args with `journalctl -u k3s`, which finds nothing on k3d because k3s runs as PID 1 without journald. The runner now copies the `Running kube-*` lines from `docker logs` of the server node into the `kube-bench-journal` ConfigMap, and the Job puts a `journalctl` that prints them first on `PATH`; the args already met those checks. The step skips four checks, each with its reason in `k3s-checks.sh`: 1.1.20 (k3s writes public `*.crt` files 0644), 5.1.1 (Flux binds cluster-admin), 5.1.3 (wildcards in Flux, Flagger and Kubernetes aggregate roles) and 5.1.6 (operators need mounted tokens).
- CIS 5.1.5: every `default` ServiceAccount outside kube-system sets `automountServiceAccountToken: false`. Each platform `namespace.yaml` declares it next to its Namespace, the tenant component adds it to every tenant namespace, the Flux lockdown component adds it to `flux-system`, and `platform_label_system_namespaces` applies it to `default`, `kube-public` and `kube-node-lease`. No workload on a default ServiceAccount calls the Kubernetes API: the Kyverno test hooks only probe HTTP, and RustFS, the restore-test Pushgateway, PostHog's ClickHouse, Redpanda, PostgreSQL, Redis, ZooKeeper and migrate Job don't use it. The kube-bench Job runs as the `kube-bench` ServiceAccount, which may only list ServiceAccounts, so the 5.1.5 audit can read them. New convention rule `default-service-account` fails a Namespace without such a ServiceAccount in its universe.
- The ephemeral platform-e2e Falco noise check counts only events from this cluster: events with a Kubernetes namespace, plus events whose `container.id` is one of the run's k3d node containers (k3s and containerd run in the node's `docker-<id>.scope` cgroup). Falco sees every process on the host, and another session's Docker builds (`nvidia-cdi-hook` ldconfig, buildkitd's qemu check) failed the step with `k8s_ns_name=<NA>` events. `falco-events.sh` gains `--node-container-id`.
- CloudNativePG chart 0.29.2 with operator 1.30.2 (`sha256:f96f6be3d81ec93819b443c665c575c609342fca840df90d4d87dae314a5b913`). The operator image no longer carries the five Go findings 1.30.1 had, so its `image-findings.toml` entry is gone. The chart change only rewords the single-namespace notes in its README.
- Traefik chart 42.4.1. It renders the same objects as 42.4.0 apart from the chart label; Traefik stays on v3.7.19. Every other platform chart, image and tool in `deploy/tools.toml` is on its newest stable release as of 2026-11-17.

## [0.27.3] - 2026-11-17

- `BaukitCnpgWalArchiveStale` no longer fires on an idle database. It needs the last archival older than 15 minutes and WAL waiting for it: a pending `.ready` file (`cnpg_collector_pg_wal_archive_status{value="ready"}`) or a failed attempt newer than the last success. PostgreSQL skips the `archive_timeout` switch when nothing was written, so platform-local fired with `failed_count` 0 and an empty archive queue.
- `BaukitPostgresRestoreTestStale` counts a missing restore proof only once `kube_cronjob_created` for `postgres/postgres-restore-test` is older than 35 days. A recreated cluster fired for up to a month before the first monthly run. A stale proof, and a missing one on an older cluster, still fire.
- Falco `Baukit secret read by unexpected service account` lets `flagger-system:flagger` get Secrets outside the platform namespaces. Flagger reads the Secrets a canary target references to copy them for the `-primary` workload, and on platform-local it was the only service account that fired the rule in 12 h (203 gets on `leitbild-runtime`). A list or watch by Flagger, or a get in a platform namespace, still fires. A replay test covers both cases.
- PostHog web, events and plugins pass the restricted Kyverno policies. A post-renderer patch sets the pod to `runAsNonRoot` as uid 999 and gid 1000, the `posthog` user the image already runs as, with seccomp `RuntimeDefault`. Every container, init containers included, drops `ALL` capabilities and disallows privilege escalation. The `wait-for-service-dependencies` and `wait-for-migrations` init containers get requests and limits, which the chart cannot set. The `posthog-migrate-*` hook Job gets the same pod and container settings and init container resources. The post-renderer drops the `posthog-grafana-annotation-job-post-*` hook Job: chart 30.46.0 renders it without the Grafana, Loki and Promtail guard its pre twin has, no value turns it off, and it only echoes the Helm revision for Grafana annotations the platform does not use.

## [0.27.0] - 2026-11-17

- On WSL2 the kernel's wall clock runs about 200 s per hour ahead of `CLOCK_BOOTTIME`, so `/proc/stat` btime grows and every Go exporter's `process_start_time_seconds` moves without a restart. That fired the upstream `AlertmanagerClusterCrashlooping` on platform-local. The platform pack has a `wsl` component, off by default and on in the local overlay, with `BaukitWslStartTimeDriftInhibitor`. The local routing inhibits the crashloop alert with it and drops it in `blackhole`. It stays silent once a container restarts, when the start time jumps further than CrashLoopBackOff allows, or when btime is stable, so a real crashloop still fires. The Alertmanager config check accepts a blackhole route for any alertname that only serves as an inhibit source.
- Pin bumps to the newest stable releases: kube-prometheus-stack chart 93.3.0 to 93.3.1 (Grafana subchart 14.4.2), Loki chart 21.2.3 to 21.3.1, rustfs 1.0.5 to 1.0.6, aws-cli 2.40.3 to 2.40.4, traefik/whoami v1.11.0 to v1.12.0 in the `traefik-edge` e2e suite, and the njs vector image nginx 1.31.6 to 1.31.8. The e2e echo image moves from `nginxinc/nginx-unprivileged:1.29.3-alpine` to `nginx/nginx-unprivileged:1.31.8-alpine`, the same image as the Loki gateway. `local-git-http.Dockerfile` pins `alpine:3.24.4` by digest instead of a bare tag.
- busybox 1.38.0, `ghcr.io/cloudnative-pg/postgresql:18.7-system-trixie`, `postgres:14.25-alpine` and `redis:6.2.24-alpine` move to upstream's rebuilt digests. The redis rebuild has no HIGH or CRITICAL findings left, so its allowlist entry is gone. The postgres rebuild clears the Alpine package findings and still carries 26 Go standard library CVEs in its bundled `gosu`.
- `image-findings.toml` entries for findings with no fixed upstream release as of 2026-11-17 now expire on 2027-01-16 and name the image version. Rescanned against the Trivy DB of 2026-11-17. The `templates/web/web/Dockerfile` entry is gone: the template sets `USER 101` (DS-0002).

## [0.26.4] - 2026-11-16

- `platform-lifecycle.sh up` refuses a leftover Docker network `k3d-<cluster>` whose subnet is not `PLATFORM_SUBNET`, because k3d would reuse it and ignore `--subnet`. The error prints `docker network rm k3d-<cluster>`; the script never removes the network itself. A leftover on the right subnet is reused as before.
- Falco reads Kubernetes audit events (FA6). A new HelmRelease `falco-k8saudit` runs the k8saudit plugin 0.18.0 (installed by digest with cosign verification) in a non-root Deployment and forwards to the existing falcosidekick, so events reach Loki and Alertmanager with `eventsource="k8s_audit"`. New rules: secret read by an unexpected service account (Warning), exec or attach into a pod (Warning), ClusterRoleBinding change outside Flux (Critical). Execs into `postgres` by the postgres-restore-test CronJob and the CNPG operator are expected and stay quiet; any other exec into `postgres` still fires. New alert `BaukitFalcoK8sAuditDown` with runbook `falco-k8saudit-down`, and e2e suite `falco-audit`.
- `k3s/audit-policy.yaml` is stricter: it skips the `RequestReceived` and `ResponseStarted` stages, drops self access reviews and service account reads of anything but Secrets, ConfigMaps and tokens, and logs exec, attach and port-forward at `Metadata`. Secrets stay at `Metadata`, so no body reaches the log or Falco. Node and kube-system reads now really are dropped: a rule naming users and userGroups needs both to match, so the old combined rule never fired. On the platform-local cluster the log fell from about 21 to 7.6 events per second.
- Local clusters send audit events to `http://10.43.0.60:9765/k8s-audit` (`k3s/audit-webhook.yaml`). Existing clusters keep their old flags until `down --delete` and `up`.
- Overlays that compose the falco base must also compose `components/network-policy/node-cidr`, which fills the webhook ingress policy.
- platform-infra must add these k3s server flags, ship `audit-policy.yaml` and `audit-webhook.yaml` to the node, and keep the k3s default service CIDR `10.43.0.0/16` (or change the ClusterIP in both files):
  `--kube-apiserver-arg=audit-policy-file=<dir>/audit-policy.yaml`, `--kube-apiserver-arg=audit-webhook-config-file=<dir>/audit-webhook.yaml`, `--kube-apiserver-arg=audit-webhook-batch-max-wait=5s`. The falco namespace needs HTTPS egress to ghcr.io and the sigstore endpoints for the plugin download.
- Breaking: Prometheus sets `enforcedNamespaceLabel: namespace`. Every series a tenant ServiceMonitor scrapes carries the monitor's namespace, written after the tenant's relabelings and metric relabelings, and tenant PrometheusRules only see their own namespace. ServiceMonitors, PodMonitors and PrometheusRules in cert-manager, cnpg-system, falco, flagger-system, kube-system, kured, kyverno, observability, observability-agents, platform-redis, postgres, posthog and traefik are in `excludedFromEnforcement`, so kube-state-metrics, the control-plane monitors and the platform rules keep their labels. A consumer that adds monitors or rules in another platform namespace adds it to that list; e2e `flux-tenancy` fails on a non-tenant namespace the list misses.
- Breaking: `restrict-tenant-servicemonitors` also denies `honorLabels: true`, a relabeling or metric relabeling that writes `namespace`, a `targetLabel` with `$` and `labelmap`. baukit-app's ServiceMonitors now set `honorLabels: false`.
- Breaking: `restrict-tenant-metric-templates` requires every series selector in a tenant query to contain `namespace="{{ namespace }}"` (spaces inside the braces and around `=` are allowed), and denies a query without a selector or with a bare `metric[range]`. Before, a tenant ServiceMonitor could stamp another product's `product` and `service` labels on its series and skew that product's canary analysis (threat model P-13).
- Breaking: `restrict-tenant-traefik-routes` covers IngressRouteTCP and compares `Host`, `HostHeader` and `HostSNI` arguments in either quote style, lowercased, trimmed and without a trailing dot, against IngressRoutes, IngressRouteTCPs and Ingresses in other namespaces. It denies `HostRegexp`, `HostSNIRegexp` and `HostSNI(`*`)` in tenant namespaces, because whether a pattern overlaps another tenant's host is not decidable in the policy. Tenants still hold no RBAC for IngressRouteTCP or IngressRouteUDP (threat model P-10). The traefik base adds ClusterRole `baukit-kyverno-traefik-tcp-view` (get, list, watch on ingressroutetcps), aggregated only into the Kyverno admission, background and reports controllers, so the policy can list them.
- Prometheus selects ServiceMonitors and PodMonitors in every namespace (`{}`), not only in namespaces labelled `app.kubernetes.io/part-of=baukit-platform`. Before, monitors in tenant namespaces were never scraped. `ruleNamespaceSelector` stays platform-only: tenants cannot create PrometheusRules, and Alertmanager routes to security-pager and security-tickets on rule labels. The e2e-tenant namespace drops the platform label, so it looks like a product namespace.
- e2e `flux-tenancy` expects the new rules to deny. Step `namespace-label-is-enforced` reads the generated Prometheus config to check that a tenant ServiceMonitor's job sets `namespace` after its own relabelings, then checks through the Prometheus API that the target is up and that the echo exporter's `namespace="spoofed"` series is stored with `namespace="e2e-tenant"`.

## [0.26.3] - 2026-11-16

- Tenant `flux-reconciler` accounts can manage the kinds baukit-app products ship. The flagger base adds ClusterRoles `baukit-tenant-flagger-edit` and `-view` (canaries, metrictemplates), the traefik base `baukit-tenant-traefik-*` (ingressroutes, middlewares, traefikservices) and the observability-stack base `baukit-tenant-monitoring-*` (servicemonitors). The edit roles aggregate into `admin` and `edit`, the view roles into `admin`, `edit` and `view`. Before, a tenant reconcile failed with `cannot patch resource "canaries"` and the same for the other kinds. A cluster without one of these bases carries none of its roles.
- New Kyverno policies for tenant namespaces, because those objects run with a platform controller's identity: `restrict-tenant-servicemonitors` denies a `namespaceSelector` beyond the own namespace, `bearerTokenFile`, `tlsConfig` file paths, `proxyUrl` and relabelings that write `__address__`; `restrict-tenant-metric-templates` allows only the `prometheus` provider at the platform Prometheus address or no address; `restrict-tenant-traefik-routes` allows forwardAuth only to a Service in the own namespace, denies `plugin` middlewares, and denies an IngressRoute `Host()` that an IngressRoute or Ingress in another namespace already serves. Tenants that use any of these need to move them into their namespace before upgrading.
