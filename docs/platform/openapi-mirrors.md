# Raw OpenAPI mirrors

**Status:** Design only. Do not schedule implementation until a second product has a raw-schema consumer.
**Applies to:** Committed byte copies of a product's canonical OpenAPI document.
**Related:** [Strict quality profile](./strict-quality-profile.md) and the [CLI README](../../cli/README.md).

## Keep mirrors separate from declarations

`openapi.consumers` lists outputs produced by `openapi-typescript`. A raw JSON copy has different contents, tooling, and package use. Treating a copy as a consumer would either run the TypeScript generator against the wrong path or add path-specific branches to declaration generation.

If another product needs a committed raw schema inside a package, add an optional `openapi.mirrors` list:

```toml
[openapi]
schema = "backend/openapi.json"
consumers = [
  "generated/openapi.d.ts",
  "mobile/src/api/schema.d.ts",
]
mirrors = [
  "mcp/openapi.json",
  "extension/openapi.json",
]
```

An absent list and `mirrors = []` mean no mirrors. Existing manifests and the `openapi.typescript` compatibility fallback retain their current behavior.

The source schema remains the only authored file. A mirror must contain exactly the same bytes, including whitespace, final newline, and object-key order. The check does not parse or normalize JSON. Each destination must differ from the schema path, from every declaration consumer path, and from every other mirror path.

## Path containment

Every schema, consumer, and mirror path is relative to the product root. Validation rejects an empty path, an absolute path, a parent component, and a platform prefix. Lexical checks are not enough because an in-root symlink can point outside the repository.

Before reading or writing a path, the CLI should canonicalize the product root and the target. If an output does not exist yet, it should canonicalize the nearest existing parent and append only validated normal components. The resolved target or parent must stay under the canonical product root. An existing symlink that resolves outside the root fails validation. No command may follow it to read or overwrite the external file.

Duplicate and overlapping destinations are manifest errors. Error messages may name the manifest path but must not print schema bytes.

## Doctor and strict CI

`baukit doctor` remains read-only. For every mirror it should:

1. apply the containment rules to the schema and destination;
2. require both files to exist as regular files; and
3. compare their complete byte sequences.

A missing mirror, escaped path, duplicate destination, overlap with a declaration consumer, read error, or byte difference makes doctor fail. A byte difference should report `OpenAPI mirror '<path>' differs from '<schema>'` without including a content diff. Declaration consumers still receive only existence and containment checks in doctor because their generated bytes are not equal to the schema.

The strict gate should keep three steps distinct:

1. Regenerate the canonical schema and fail if it differs from the committed schema.
2. Run `baukit generate openapi-client` for `openapi.consumers` and fail on declaration drift.
3. Run a separate `baukit generate openapi-mirrors` command that copies the canonical bytes to `openapi.mirrors`, then require every mirror to be committed and fail on mirror drift.

The mirror command should validate every source and destination before writing any file and read one source snapshot per invocation. For each destination, it should copy to a temporary sibling, flush and close it, then rename it over the destination. If one replacement fails, the command removes that temporary file and leaves that destination unchanged. Earlier destinations may already contain the new bytes; rerunning the command converges them. Concurrent commands may race on replacement, but no destination contains a partial file. The strict byte check decides the final result.

Tests must cover absent and empty lists, multiple mirrors, byte differences, missing and untracked mirrors, absolute and parent paths, symlink escape, duplicate paths, consumer overlap, partial copy failure, concurrent commands, and filenames containing spaces. Artifact tests must pack or build the consuming package and prove that the raw schema is present in the installed output.

## Current product mapping

Tiefgang has one canonical `backend/openapi.json`. Its manifest correctly lists three TypeScript declarations under `openapi.consumers`.

Raw copies use separate product glue:

- `scripts/openapi-client.sh` copies the schema to `mcp/openapi.json` before generating declarations.
- `extension/scripts/copy-openapi.mjs` copies the schema to `extension/openapi.json`.
- `extension/scripts/check-openapi.mjs`, `extension/test/contracts.test.ts`, and `scripts/quality-gate.sh` repeat byte-drift checks.

With `openapi.mirrors`, Tiefgang could delete those two copy scripts or copy steps and the duplicate byte checks. Package-specific tests that assert the file is shipped should remain.

MCP generation does not depend on this feature. A generated MCP package can use its declaration registered in `openapi.consumers`, and a product can keep a local copy command if its package reads raw JSON.

Adoption is additive. A product adds `mirrors`, runs the separate mirror command, and keeps its current copy script until the new strict gate passes. It can then delete the local copy and equality checks. Products without `mirrors` see no new files or commands in their quality run.

## Evidence needed for implementation

A second product must have a committed raw OpenAPI copy inside an MCP server, extension, SDK, or another published or tested artifact. Its build or runtime must read the JSON copy. Another generated TypeScript declaration, a deployed schema endpoint, or a speculative package layout does not count.

The second product mapping must name its canonical schema, copy command, drift check, package inclusion test, and deletion after adoption. Its paths must fit the list and containment rules without a product switch. Baukit should then implement both mappings in fixtures and test packed artifacts before release.

## Decision

Keep raw OpenAPI copying in Tiefgang for now. Add `openapi.mirrors`, the separate generation command, doctor validation, and strict CI wiring only after the second concrete consumer described above exists.
